# Frontend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the laufenden website — a Next.js App Router site reading the content pipeline's committed JSON, in 9 languages, across Global/Germany-national/16-Bundesländer regions, in a "Classic Editorial" (NYT-inspired) visual style.

**Architecture:** Next.js (App Router, TypeScript, static generation) added into the existing repo alongside the content pipeline. A thin `lib/content.ts` data layer reads `content/articles/**/*.json` directly via `fs` — no database, no API route. Tailwind CSS v4 (CSS-first `@theme` config, no `tailwind.config.js`) provides the design tokens for the visual system. A one-off script reuses the pipeline's already-tested `translate.ts` (MyMemory) to generate the UI chrome dictionary for all 9 languages from a hand-written English base.

**Tech Stack:** Next.js (App Router), React, TypeScript, Tailwind CSS v4, Vitest (already in the repo).

**Spec:** `docs/superpowers/specs/2026-08-21-laufenden-news-platform-design.md` (see "Frontend (Next.js on Vercel)" and "Visual design system" sections)

## Global Constraints

- **Routing**: `/[lang]` (home), `/[lang]/[region]` (category/state listing), `/[lang]/[region]/[slug]` (article). `lang` ∈ `en | de | tr | uk | hi | bn | pl | es | fr` (from `shared/languages.ts`'s `LANGUAGES`). `region` ∈ `global | germany | <16 Bundesländer>` (from `shared/regions.ts`'s `REGION_PRIORITY`). Root `/` redirects to `/en`. An invalid `lang` or `region` segment calls `notFound()`.
- **Next.js dynamic route params are async** (Next.js 16): every page/layout component receiving `params` types it as `Promise<{...}>` and does `const {...} = await params`.
- **No pagination in v1** — category/region listings cap at the 100 most recent articles for that region+language.
- **Data layer**: `lib/content.ts` reads `content/articles/**/*.json` directly via Node `fs` — no database, no API route. Every reading function accepts an optional `articlesDir` parameter (defaulting to the real `content/articles` path) so it's testable against fixture directories, matching the content pipeline's existing dependency-injection pattern.
- **Empty states are mandatory**: any listing with zero articles renders a real "no articles yet" message (from the dictionary), never a blank page or a crash.
- **UI chrome dictionary**: `shared/dictionaries/{lang}.json`, one file per language, all 9 keyed identically to `shared/dictionaries/en.json`. The 8 non-English files are generated by reusing `content-pipeline/src/translate.ts`'s `translateText` (MyMemory) — never hand-authored — and committed to the repo as static JSON, imported directly (not read via `fs` at request time).
- **Visual system** ("Classic Editorial", chosen from mockup review): headlines in Playfair Display (700/900), deck/subhead text in Lora italic, body/UI text in Inter, masthead red `#b3121b` as the sole accent, hairline black rules between sections, small-caps uppercase section/region labels. Hindi (`hi`) and Bengali (`bn`) headlines use Noto Serif Devanagari / Noto Serif Bengali respectively instead of Playfair Display, since it doesn't cover those scripts. These are Tailwind v4 `@theme` tokens (`--font-serif`, `--font-serif-hi`, `--font-serif-bn`, `--font-deck`, `--font-sans`, `--color-masthead`), not inline styles.
- **Scaffolding**: Next.js, React, and Tailwind are added into the *existing* `package.json`/`tsconfig.json` (which already serve the content pipeline's Vitest setup) — never regenerated fresh via `create-next-app`. Every task must leave the content pipeline's own tests (`npm test` covering `content-pipeline/test/**`) passing unchanged.
- **Testing scope**: Vitest unit tests for `lib/content.ts`, `lib/dictionary.ts`, and `scripts/generate-dictionaries.ts` only — no component-rendering tests (no jsdom, no React Testing Library). Every page-building task ends with a manual `npm run dev` browser check of the actual page before being considered done — type-checking and unit tests verify correctness, not that a page renders and looks right.
- Real content already exists in the repo (`content/articles/2026-08-21/`, 20 articles from the live pipeline) — use it for manual verification; some articles only have 1-2 of 9 translations (real MyMemory rate-limiting from before `MYMEMORY_EMAIL` was registered), which is a genuine, useful test case for the translation-fallback UI, not a data problem to work around.

```typescript
import { readFile, writeFile } from 'node:fs/promises';
import path from 'node:path';
import { pathToFileURL } from 'node:url';
import { translateText } from '../content-pipeline/src/translate';
import type { TranslateOptions } from '../content-pipeline/src/translate';
import { LANGUAGES } from '../shared/languages';

const DEFAULT_DICTIONARIES_DIR = path.join(process.cwd(), 'shared', 'dictionaries');

export async function generateDictionary(
  base: Record<string, string>,
  targetLang: string,
  options: TranslateOptions = {}
): Promise<Record<string, string>> {
  const result: Record<string, string> = {};
  for (const [key, value] of Object.entries(base)) {
    const translated = await translateText(value, 'en', targetLang, options);
    result[key] = translated ?? value;
  }
  return result;
}

export async function generateAllDictionaries(dictionariesDir: string = DEFAULT_DICTIONARIES_DIR): Promise<void> {
  const baseRaw = await readFile(path.join(dictionariesDir, 'en.json'), 'utf-8');
  const base = JSON.parse(baseRaw) as Record<string, string>;
  const email = process.env.MYMEMORY_EMAIL;
  const targets = LANGUAGES.filter((lang) => lang !== 'en');

  for (const lang of targets) {
    const dict = await generateDictionary(base, lang, { email });
    await writeFile(path.join(dictionariesDir, `${lang}.json`), `${JSON.stringify(dict, null, 2)}\n`, 'utf-8');
    console.log(`Wrote ${lang}.json`);
  }
}

if (process.argv[1] && import.meta.url === pathToFileURL(process.argv[1]).href) {
  generateAllDictionaries().catch((err) => {
    console.error(err);
    process.exitCode = 1;
  });
}
```

```typescript
import type { LanguageCode, Region } from '../shared/types';
import en from '../shared/dictionaries/en.json';
import de from '../shared/dictionaries/de.json';
import tr from '../shared/dictionaries/tr.json';
import uk from '../shared/dictionaries/uk.json';
import hi from '../shared/dictionaries/hi.json';
import bn from '../shared/dictionaries/bn.json';
import pl from '../shared/dictionaries/pl.json';
import es from '../shared/dictionaries/es.json';
import fr from '../shared/dictionaries/fr.json';

const DICTIONARIES: Record<LanguageCode, Record<string, string>> = {
  en, de, tr, uk, hi, bn, pl, es, fr,
};

export function getDictionary(lang: LanguageCode): Record<string, string> {
  return DICTIONARIES[lang] ?? DICTIONARIES.en;
}

export function t(lang: LanguageCode, key: string): string {
  return getDictionary(lang)[key] ?? DICTIONARIES.en[key] ?? key;
}

export function getRegionDisplayName(lang: LanguageCode, region: Region): string {
  return t(lang, `region.${region}`);
}
```

```typescript
import { readFile, readdir } from 'node:fs/promises';
import path from 'node:path';
import type { Article, LanguageCode, Region } from '../shared/types';

const DEFAULT_ARTICLES_DIR = path.join(process.cwd(), 'content', 'articles');

export interface DisplayFields {
  title: string;
  summary: string;
  isFallback: boolean;
}

export async function getAllArticles(articlesDir: string = DEFAULT_ARTICLES_DIR): Promise<Article[]> {
  let dateDirs: string[];
  try {
    dateDirs = await readdir(articlesDir);
  } catch {
    return [];
  }

  const articles: Article[] = [];
  for (const dateDir of dateDirs) {
    const fullDateDir = path.join(articlesDir, dateDir);
    let files: string[];
    try {
      files = await readdir(fullDateDir);
    } catch {
      continue;
    }
    for (const file of files) {
      if (!file.endsWith('.json')) continue;
      try {
        const raw = await readFile(path.join(fullDateDir, file), 'utf-8');
        articles.push(JSON.parse(raw) as Article);
      } catch {
        continue;
      }
    }
  }
  return articles;
}

function sortByRecency(articles: Article[]): Article[] {
  return [...articles].sort((a, b) => new Date(b.publishedAt).getTime() - new Date(a.publishedAt).getTime());
}

export async function getArticlesByRegion(
  region: Region,
  limit = 100,
  articlesDir: string = DEFAULT_ARTICLES_DIR
): Promise<Article[]> {
  const all = await getAllArticles(articlesDir);
  return sortByRecency(all.filter((a) => a.category === region)).slice(0, limit);
}

export async function getRecentAcrossRegions(
  regions: Region[],
  limit: number,
  articlesDir: string = DEFAULT_ARTICLES_DIR
): Promise<Article[]> {
  const all = await getAllArticles(articlesDir);
  const regionSet = new Set(regions);
  return sortByRecency(all.filter((a) => regionSet.has(a.category))).slice(0, limit);
}

export async function getArticleBySlug(
  region: Region,
  slug: string,
  articlesDir: string = DEFAULT_ARTICLES_DIR
): Promise<Article | null> {
  const all = await getAllArticles(articlesDir);
  return all.find((a) => a.category === region && a.slug === slug) ?? null;
}

export function getDisplayFields(article: Article, lang: LanguageCode): DisplayFields {
  const translated = article.translations[lang];
  if (translated) {
    return { title: translated.title, summary: translated.summary, isFallback: false };
  }
  const original = article.translations[article.originalLanguage];
  if (original) {
    return { title: original.title, summary: original.summary, isFallback: true };
  }
  return { title: article.slug, summary: '', isFallback: true };
}
```
